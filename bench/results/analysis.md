# Phase 0 벤치마크 분석 (2026-11-16)

원자료: [`summary.md`](./summary.md), [`results.json`](./results.json). 실행: `python bench/run_bench.py --control --route-timeout 420` (kit_dev_coldfire는 넥다운 선폭 수정 후 재측정).

## 실험 조건

- **보드:** KiCad 10 공식 데모 8개 (부품 15~160개, 2~4층).
- **NOAH 조건:** 커넥터·장착 홀·피듀셜만 원래 위치에 고정하고, 나머지 부품은 **무작위 위치에서 시작**. 4개 시드 병렬 어닐링 → 2단계 Freerouting 배선(단계당 420초 제한) → kicad-cli DRC.
- **대조 조건:** 사람이 만든 원본 배치를 그대로 두고 같은 배선·검증 파이프라인 실행.
- **환경:** 4코어 CPU 컨테이너, GPU 없음. 각 보드 1회 실행.

## 핵심 결과

| 구분 | 결과 |
|---|---|
| 무인 완주 | 8개 보드 모두 배치→배선→DRC→리포트→제조 파일까지 사람 개입 없이 끝까지 실행됨 |
| 완전 배선 (미배선 0) | **4/8** (ecc83, sonde_xilinx, pic_programmer, complex_hierarchy). 근접 2개 (interf_u 5, kit_dev_coldfire 5) |
| 전기 DRC 0건 | **3/8** (ecc83, sonde_xilinx, pic_programmer) |
| 소요 시간 | 부품 68개 이하·배선이 쉬운 보드는 **12초~2.6분**. 배선이 어려운 보드는 배선 시간 제한(2단계 × 420초)에 걸려 13~14분 |
| 배치 속도 | 4개 시드 병렬, 5.6~70초 (부품 15~160개) |
| 배선 길이 추정치(HPWL) | 사람 원본 대비 0.89~1.20배 (stickhub 제외) |
| 설계 근거 문장 | 105개 생성, 105개 검증 통과, 제외 0개 |

MODI Factory가 밝힌 처리 시간(약 90분)과 비교하면 속도는 충분히 빠르지만, **완성도는 아직 실사용 수준이 아닙니다.** 8개 중 4개만 완전 배선, 3개만 전기 DRC 0건입니다.

## 대조 실험이 보여 준 것: 병목은 보드마다 다르다

| 보드 | NOAH 배치 (미배선/전기 DRC) | 원본 배치 (미배선/전기 DRC) | 판단 |
|---|---|---|---|
| ecc83, sonde_xilinx, pic_programmer | 0/0 | 0/0 | 차이 없음 |
| interf_u | 5/7 | 0/3 | **배치가 병목** |
| complex_hierarchy | 0/8 | 0/0 | **배치가 병목** |
| kit_dev_coldfire | 5/4 | 0/3 | **배치가 병목** |
| stickhub | 43/186 | 3/0 | **배치 모델의 한계** (면적 96%/191%) |
| multichannel_mixer | 131/7 | 160/1 | **배선기가 병목** (사람 배치로도 실패) |

- 배치가 병목인 보드에서 NOAH 배치는 배선 길이 추정치(HPWL)로는 사람과 비슷하거나 더 짧은데도(0.89~1.03배) 배선이 덜 끝납니다. **배선 길이 같은 간접 지표만 줄여서는 "배선 가능한 배치"를 보장하지 못한다**는, 조사 보고서의 학술적 한계 분석(모디팩토리 핵심 특허의 연결선 길이·밀도·교차 지표에 대한 지적)과 같은 현상입니다. 혼잡도(routability) 추정을 비용에 넣어야 합니다.
- multichannel_mixer는 사람 배치로도 미배선 160개입니다. 이 보드의 한계는 Freerouting(시간 제한·2층·0.3 mm 규칙)에 있습니다.

## 구현 중 발견해 고친 문제 (11건)

자세한 내용은 [`docs/architecture.md`](../../docs/architecture.md) §15.2. 대부분 **KiCad ↔ Freerouting 사이의 변환 손실**이었습니다: 격자 밖 좌표, 구리 텍스트·사용자 규칙·최소 선폭 누락, 구리 영역 처리, 넷클래스와 보드 최소 규칙 불일치, µm 반올림, 시간 초과 시 결과 유실. 오픈소스를 조립해 서비스를 만들 때 실제 비용이 어디서 생기는지 보여 주는 결과입니다.

## 지표 해석 시 주의

- **디커플링 통과율:** NOAH가 사람 원본보다 높게 나옵니다(예: interf_u 2/4 vs 0/4). 그러나 사람 원본이 대부분 기준(3 mm)을 못 넘는 것은 기준이나 측정 방식(가장 가까운 전원 핀까지 직선거리)이 실무와 맞지 않을 수 있다는 뜻입니다. PCB 전문가와 규칙을 보정해야 합니다.
- **근거 문장 제외 0개:** 현재 문장은 증거에서 템플릿으로 만들기 때문에 제외가 거의 나오지 않는 것이 정상입니다. 검증기의 실제 역할은 Phase 1에서 LLM이 문장을 쓸 때 드러납니다.
- **1회 실행:** 시드에 따라 결과가 달라집니다(예: interf_u는 이전 실행에서 미배선 0). 반복 측정과 분산 보고가 필요합니다.

## 다음 단계 (우선순위)

1. **배선 가능성을 고려한 배치:** 혼잡도 추정(예: RUDY)을 비용에 추가하고, 배치 병목 보드(interf_u, complex_hierarchy, kit_dev_coldfire)로 대조군과의 차이를 줄인다. Cypress(GPU) 비교 포함.
2. **배선 후처리:** 끊긴 트랙 조각(track_dangling) 제거, 열 차단 스포크 확보(starved_thermal).
3. **배선기 한계 대응:** multichannel_mixer 같은 보드에 대해 시간 예산·비아 비용·층 설정 조정, 다회 실행, 대체 배선기 평가.
4. **고밀도 보드:** 실제 코트야드 다각형 충돌 검사, 45° 부품 처리, 기존 배치 국소 개선 모드 고도화.
5. **벤치마크 확대:** 30개 이상 공개 KiCad 프로젝트(라이선스 확인), 보드당 다회 실행.
6. **규칙 보정:** 디커플링·커넥터 규칙을 PCB 전문가와 함께 보정.
