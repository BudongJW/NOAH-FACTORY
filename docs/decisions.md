제품 기획서 §13 "결정이 필요한 사항"을 권장안으로 확정한 기록입니다. 각 결정은 Phase 0 검증 결과에 따라 다시 열 수 있습니다.

|---|---|

## D1. 초기 타깃 사용자

- **결정:** 하드웨어 스타트업 개발자(P1)를 핵심 타깃으로, 메이커·학생(P2)을 무료 사용자 기반으로 삼는다.
- **이유:** 지불 의사와 고통(외주 비용·대기 시간)이 가장 크고, 피드백 루프가 빠르다.
- **다시 열 조건:** 베타에서 P1 유료 전환 의향이 낮을 때.

## D2. MVP 진입 범위

- **결정:** MVP는 **기존 KiCad 파일 → 배치·배선 → 검증 → 근거 리포트 → 내보내기**로 시작한다. 요구사항 → 회로도 생성은 Phase 2에서 추가한다.
- **이유:** 배치·배선·검증 엔진과 근거 체계는 엔드투엔드 흐름의 공통 기반이다. 이 기반 없이 회로도 생성부터 만들면 결과를 검증할 수단이 없다. 또한 MODI Factory와 같은 범위에서 품질·속도·근거를 직접 비교할 수 있다.
- **다시 열 조건:** 베타 사용자 다수가 "회로도가 없어 시작을 못 한다"고 답할 때.

## D3. EDA 지원 순서

- **결정:** KiCad 우선. Altium은 Phase 2.
- **이유:** KiCad는 오픈 포맷·CLI(`kicad-cli`)·Python API(`pcbnew`)로 무인 자동화가 가능하고, 국내외 연구(KAIST, LG AI연구원)와 오픈소스 생태계가 KiCad로 모이고 있다.

## D4. 배치 엔진

- **결정:** CPU 기반 시뮬레이티드 어닐링 + 규칙 기반 보정으로 시작한다. Cypress(GPU, Apache-2.0)는 벤치마크로 비교한 뒤 도입 여부를 정한다.
- **이유:** 인프라 부담 없이 Phase 0 측정을 시작할 수 있고, 비교 기준선(baseline)이 된다.

## D5. 배선 엔진

- **결정:** Freerouting(GPL-3.0)을 별도 프로세스로 헤드리스 실행한다.
- **이유:** 검증된 오픈소스 라우터이며, 연구상 학습 기반 배선기는 아직 규칙 기반보다 약하다(PCBWorld, 2026). 별도 프로세스 실행으로 라이선스 경계를 분리한다.

## D6. 설계 근거 생성

- **결정:** Phase 0에서는 **규칙 기반 템플릿**으로 근거 문장을 만들고, 모든 문장은 증거 레코드를 인용해야 한다. LLM(Claude) 문장화는 같은 검증기를 통과하는 조건으로 Phase 1에서 추가한다.
- **이유:** 검증기(Claim ↔ Evidence)가 먼저 있어야 LLM 문장의 환각을 막을 수 있다.

## D7. 제조 파트너

- **결정:** 보류. Phase 0–1은 제조사 중립 규칙 세트(일반 2·4층 공정)로 진행하고, 베타 사용자 발주처 조사 후 정한다.

## D8. 가격 정책

- **결정:** 보류. 비공개 베타는 무료로 운영하고 사용자 인터뷰로 가격 기준점을 정한다.

## D9. 팀 구성

- **결정:** Phase 0에서 PCB 실무 전문가 1인(자문 포함) 확보를 최우선으로 한다.

## D10. 혼잡도 반영 배치 (2026-11-17)

- **결정:** 배치 비용에 배선 혼잡도(RUDY) 항을 기본으로 포함한다(가중치 10, `--congestion 0`으로 끌 수 있음).
- **이유:** 사전 검증에서 용량 초과 구간이 생긴 보드가 정확히 배선에 실패한 보드였고, A/B(배치 병목 3개 보드 × 시드 세트 2개)에서 미배선 합계가 26 → 13으로 줄었다. 대가는 배선 길이 추정치 0~15% 증가.
- **다시 열 조건:** 보드 수와 반복 횟수를 늘린 벤치마크에서 효과가 사라지거나, 배선 길이 증가가 SI 등 다른 품질 문제로 이어질 때.
